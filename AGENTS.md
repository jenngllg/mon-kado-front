# MonKado frontend instructions

Read and apply [the shared MonKado instructions](../mon-kado/AGENTS.shared.md), which supplement Jenn's global preferences in `~/.codex/AGENTS.md`. This file adds frontend-specific rules.

- Read `DESIGN_SYSTEM.md` before creating or changing any interface. Apply it to existing screens and new features; user-approved refinements take precedence over older mockups.
- Reuse the existing tokens and shared controls. Match the original mockup layouts and illustrated cards; do not simplify or reinterpret them without an explicit request. Keep the user's requested page actions at the top right and never underline navigation, buttons, tabs or action links in any state.
- Keep real prose links distinguishable, preserve keyboard focus and accessible names.
- Do not add plant, leaf or botanical drawings as site decoration, including page backgrounds, list overviews and shared/group views. Preserve occasion-cover photographs and member-provided images.

- Keep interface copy concise. Avoid redundant explanations and obvious field instructions; do not add helper text by default.
- Preserve useful validation errors, accessibility labels and necessary legal information. Show constraints when they help resolve an error rather than repeating them under every field.
- Mark required fields with an asterisk; do not append “facultatif” to optional field labels.
- Call wishlist entries “souhaits” in interface labels, actions and feedback; reserve “cadeaux” for general gift-related marketing copy.

- Browser tabs for wishlist and wish detail/edit pages use the loaded resource name followed by ` · MonKado`, including shared views; keep titles current after saved renames and prevent stale responses from changing another page's title.

- The home/header logo combines the existing MonKado wordmark and coral dot with the favicon gift outline in coral on its left, shifted upward by 1 px for optical alignment.
